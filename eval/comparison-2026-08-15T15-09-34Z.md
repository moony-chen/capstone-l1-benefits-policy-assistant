## The Q05 finding — window dilution

With ~150-word windows over ~950 words of policy text, 7 windows each
span ~2–3 policies, so top-4 windows surface most of the handbook. The
model answered Q05 (24 hrs/week eligibility) with an exhaustive catalog
citing 14 policy ids. Every claim is grounded (validation passed), and
the core answer is still POL-001's part-time rule, but citation sprawl
makes the answer harder to review — the opposite of Principle II's
intent (traceable, minimal citations). Retrieved lists balloon
mechanically for the same reason (window unions overlap many policies).

## Incidental fix (pre-experiment)

The first window eval attempt aborted at Q05 on a transient transport
error ("fetch failed") — the retry path only covered HTTP 5xx/429, not
connection failures. `postJson` now retries transport errors once. This
hardened both modes; the control and window runs above both ran with
the fix. No partial report was written on the failed attempt
(fail-loud behavior worked).

## Verdict

**No measured benefit to window mode; policy mode remains the default.**
Window mode matched policy mode on correctness for this question set
(15/15 same statuses, all hard cases intact) but showed citation sprawl
(Q05: 4→14 citations) and structurally diluted retrieval focus at this
handbook's scale (19 short policies; ~50 words average body). A fixed
200-token window is better suited to long documents than to a handbook
of short policies. `--chunking window` remains available as an option;
switching the default would require measured evidence this run does not
provide.

Regressions: 0 status regressions; 1 classified degradation (Q05
reviewability), no factual errors.
