# Implementation Plan: Benefits Policy Q&A Tool

**Branch**: `001-benefits-policy-qa` | **Date**: 2026-08-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-benefits-policy-qa/spec.md`

## Summary

A single-file Node.js/TypeScript assistant for the People Operations team:
it answers employee benefits questions strictly from the handbook
(`data/benefits_policies.md`), always cites POL-NNN policy ids, surfaces
conflicting/time-dependent policies instead of resolving them silently,
and explicitly declines uncovered questions. Retrieval is embedding-based
with exactly one chunk per POL-NNN policy (policies are never split) and a
local JSON embedding cache invalidated by the handbook file's hash plus
the embedding model id. Model calls go through the Perficient Portkey
gateway (OpenAI-compatible REST, native `fetch`, no SDK). An `eval` mode
runs all fifteen sample questions (`data/sample_questions.csv`) and writes
per-question records of answer, citations, and status, satisfying the
constitution's Quality Gates.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 20 LTS (installed:
v20.19.5; native `fetch` and `--env-file` available)

**Primary Dependencies**: none at runtime. Dev dependency: `tsx` (run TS
directly, no build step). Model access via native `fetch` to the Portkey
gateway — no SDK, per constitution Principle V.

**Storage**: files only — `data/benefits_policies.md` (handbook),
`data/sample_questions.csv` (eval questions), generated
`data/embeddings-cache.json` (embedding cache), generated eval reports
under `eval/`. No database or services.

**Testing**: the built-in `eval` mode over Q01–Q15 is the test harness
(constitution Quality Gates); quickstart scenarios in
[quickstart.md](./quickstart.md) are the manual acceptance checks.

**Target Platform**: any machine with Node.js ≥ 20.6 and network access to
the Portkey gateway.

**Project Type**: CLI tool (single-file implementation).

**Performance Goals**: answer a single question within seconds (SC-005);
embedding cache reused across runs when handbook hash is unchanged
(zero embedding calls on cache hit).

**Constraints**: single source file (`assistant.ts`) per constitution
Principle V; every answer grounded and cited (Principles I–II); 2025-10-01
treated as "today" (Quality Gates reference date).

**Scale/Scope**: 16 policies (POL-001..POL-016), 15 sample questions
(Q01–Q15), one user at a time.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Gate | Status |
|-----------|------|--------|
| I. Grounding-Only | Retrieval passes only handbook policy text to the LLM; system prompt forbids outside knowledge; code-level citation check rejects unsupported ids | PASS |
| II. Always Cite | Answer contract requires ≥1 POL-NNN citation; programmatic post-check (see [contracts/cli.md](./contracts/cli.md)) | PASS |
| III. Surface Conflicts | Prompt + top-k=4 retrieval designed to include both POL-007/POL-015 and both POL-016 paragraphs; quickstart scenario 1 verifies | PASS |
| IV. Decline When Uncovered | Structured `DECLINED` status with explicit not-covered message and distinct exit code | PASS |
| V. Dependency-Light | One source file (`assistant.ts`); zero runtime deps; single dev dep (`tsx`); cache/eval outputs are generated data, not source | PASS |
| VI. Evidence Standard | `eval` mode records per-question answer/citations/status (Q01–Q15); improvement loop requires before/after runs saved under `eval/` | PASS |
| Quality Gates | Eval covers all 15 questions; reference date 2025-10-01 encoded in prompt and constants | PASS |
